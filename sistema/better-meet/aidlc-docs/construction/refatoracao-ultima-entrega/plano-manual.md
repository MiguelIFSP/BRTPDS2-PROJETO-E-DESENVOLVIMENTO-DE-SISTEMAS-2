# Plano manual de testes em aparelho

Estes casos dependem de aparelho, de e-mail real ou de navegador externo, por isso não rodam no Jest. Cada caso tem ID `PM-nn` e vira linha do registro de testes da entrega ao ser executado. Aparelhos e versões ficam `[A CONFIRMAR]` até a equipe informar. Os links `bettermeet://` só abrem o app em build de desenvolvimento; no Expo Go o esquema é `exp://`, e o caso usa o campo "Código do e-mail".

## Preparação

- API de Dados com `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (endereço da API alcançável pelo celular, sem barra final e sem `/api`) e `CORS_ORIGINS` no `.env`; e-mails reais exigem `GMAIL_USER` e `GMAIL_APP_PASSWORD` (conferir o `.env.example`). Fuso das reuniões: `TZ_REUNIOES` (padrão `America/Sao_Paulo`).
- Aparelhos: Android físico `[A CONFIRMAR]` (modelo e versão do Android) e iPhone `[A CONFIRMAR]` (modelo e versão do iOS).
- Versão do sistema: commit `aed2702` com as alterações da refatoração, ou o commit da entrega `[A CONFIRMAR]`.
- Contas de teste: pelo menos duas pessoas na mesma comissão, com convite aceito para a reunião; uma delas Administrador da comissão `[A CONFIRMAR]`. Contas antigas que não são administradores precisam confirmar o e-mail no primeiro login.
